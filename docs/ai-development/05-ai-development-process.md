# 05 AI 开发执行与验收

## 1. 人和 AI 的责任边界

| 工作 | AI 可以做 | 必须人工批准 |
|---|---|---|
| PRD 分析 | 提取冲突、缺口、选项、影响 | 产品范围和最终语义 |
| OD/ADR | 起草选项、权衡、验证方案 | 最终决定和生效范围 |
| Task Card | 起草纵向切片、测试和非目标 | 开发就绪与文件范围 |
| 代码 | 在批准路径内实现并测试 | 合并、发布和生产权限 |
| 法规/认可/结论 | 提示来源和风险 | 适用性、认可、签发、合规结论 |
| AI 阈值 | 设计评估方法 | 阈值、停止条件、生产启用 |
| 验收证据 | 收集机器结果和差异 | 验收签字和上线批准 |

## 2. Definition of Ready

### Release Ready

- 唯一灯塔试点和客户/产品/市场/方法切片已经批准；
- Core、行业包、条件接口、BusinessOps 和排除项有适用矩阵；
- 技术栈、模块、数据库、部署和安全 ADR 已批准；
- 当前切片的阻塞 OD 已关闭；
- 最近 3—6 个月真实订单形成黄金场景和脱敏固定数据；
- 20 个常规、10 个异常和未来行业契约场景有稳定 ID；
- 数据分类、保留、版权和外部模型许可明确；
- 候选 release-baseline 依赖闭包完整。

### Feature Ready

- 业务结果、参与者和主要聚合明确；
- Requirement、RULE、AC、NFR、RISK 和 OD 可追踪；
- 状态机、不变量、权限、审计和错误码明确；
- API/命令/事件的输入输出和幂等语义明确；
- UI 正常、空、错误、权限、只读和并发状态明确；
- 正向、反向、边界、权限、并发、恢复测试数据明确；
- 非目标和后续 Feature 明确。

### AI Task Card Ready

`ready` 命令先做机器门禁，负责人再做语义批准：

```text
schema valid
source versions pinned
decisions approved
dependencies approved
contracts defined
test data defined
allowed paths defined
non-goals defined
product owner approved
technical/quality owner approved
```

字段齐全不等于语义正确。当前 6 张样例卡保持 BLOCKED 是正确状态。

## 3. 一张任务卡的推荐粒度

- 一个主要业务结果；
- 一个主要状态转换或核心不变量；
- 一个主要聚合拥有者；
- 最多一个跨模块公共端口变化；
- 一个 AI 代理在单次上下文内可以实现、测试和解释；
- 不依赖 AI 自行决定政策；
- 失败时可以安全回滚。

## 4. 给 AI 的执行提示模板

```text
实现任务：ATC-REC-003@1.0.0

开始前：
1. 阅读 AGENTS.md。
2. 运行 specgen validate/source-status/ready。
3. 阅读生成任务卡和所有固定依赖。
4. 检查工作区现有修改并保护用户改动。

执行约束：
- 只修改任务卡 allowed_paths。
- 不决定 OD，不修改 generated/spec。
- 不访问其他模块私有表。
- 先写失败测试，再实现。
- 覆盖正向、反向、边界、权限、并发、恢复和审计。

完成前：
- 运行任务卡 verification_commands。
- 运行 specgen check 和完整测试。
- 更新追踪和证据记录。
- 报告改动、验证、残余风险和未完成项。
```

## 5. 推荐开发循环

1. 选择一张 READY 任务卡。
2. 冻结其规格版本和 requirements lock。
3. 建立或更新契约测试。
4. 让测试先失败，证明门禁真实覆盖。
5. AI 在允许路径内实现最小改动。
6. 运行模块、契约、架构和安全测试。
7. 人工审查业务语义、数据边界和失败路径。
8. 生成验收证据并绑定代码版本、数据集哈希和规格哈希。
9. Story 进入 VERIFIED/ACCEPTED；完成证据独立保存，不写回生成任务卡。

## 6. Definition of Done

### 自动化门禁

- 编译、静态检查和依赖检查通过；
- 需求生成器二次运行无差异；
- 生成目录没有手改、缺失或未知文件；
- 正向、反向、边界、权限测试通过；
- 数量、余额、唯一采用或状态抢占涉及并发时，并发测试通过；
- 事件、接口或 AI 涉及重复、乱序、超时和恢复时，相应测试通过；
- 核心领域规则分支覆盖达到 PRD 要求；
- 模块私表零跨界、循环依赖为零；
- Must、AC 和测试之间无孤立追踪；
- 日志没有密码、令牌或未脱敏敏感正文。

### 交付门禁

- 数据迁移仅追加，升级/回滚/历史保留明确；
- API、事件、错误码和 Schema 定版；
- 页面失败态、只读态、权限态和可访问性完成；
- 审计包含主体、对象、动作、规则、前后版本和关联 ID；
- 指标、日志和异常队列能定位失败；
- 验收证据绑定构建、测试、数据集、规格、时间和批准人；
- 非目标没有被“顺手实现”；
- 历史任务和证据没有因重新生成被覆盖。

## 7. 实现中需求发生变化

- 立即停止继续扩展旧语义；
- 保留当前分支和测试证据；
- 运行 `impact`；
- 若旧版本已封存，建立新规格版本和变更任务；
- 对进行中工作决定继续旧基线、迁移或取消；
- 不能直接让 AI 按新 PRD 重写当前实现。
