# 报告签发门禁（DEV-022 / ATC-RPT-001）

用户 2026-07-27 定下三个决策后解锁报告链：**OD-011**（CNAS/CMA + 电子签名法）、**OD-022**（版本链取代）、**OD-029**（完整行级多维范围）。卡切分采用"门禁优先/签署其次"：本卡交付装配与门禁，状态止于 `PENDING_APPROVAL`；电子签名与版本链属 DEV-023。

## 三个决策的边界划分

三者原本在 PRD 中语义重叠（`撤回` 同时出现在 OD-011 与 OD-022，`认可/签发门禁` 同时出现在 OD-011 与 OD-029）。落盘时显式互相声明边界，各自 `boundary_with_sibling_decisions` 字段互指：

| 决策 | 拥有 |
|---|---|
| OD-011 | 认可体系（CNAS/CMA）、电子记录/签名可靠性三要素、报告**保留**策略 |
| OD-022 | 更正/补充/**撤回**/作废/替代五种受控动作的状态语义 |
| OD-029 | 认可范围数据粒度、权威来源、混合范围展示、**行级签发门禁** |

## 门禁是纯组合

门禁不自己判断任何上游事实，而是扇出既有的十个公开端口（决策形状统一为 `{Decision, ReasonCodes, RuleSetVersion}`），结构与 `ATC-QC-001` 同型：

```
结果采用 · QC 可报告性 · 收样放行 · 范围生产资格 · 分配状态 · 批次状态 · 仪器导入
        ↓（全部在本模块事务之外调用，gate-then-commit）
    逐项阻断 {对象, 类型, 来源, 规则集版本, 原因码, 允许的下一步, 行号}
```

每条报告行把它引用的上游版本固定在 `ReportLineGateReferences` 中，门禁按**该行当初引用的版本**回放各端口——一行永远不会被拿更新的状态去评判。

`UNKNOWN` 一律构成阻断且使整体决策为 UNKNOWN（失败关闭）；`RPT-GATE-002` 要求逐项返回，因此阻断项从不聚合为布尔值或单条汇总。

## 行级认可（OD-029 六维）

`SITE × METHOD_VERSION × PRODUCT_MATRIX × PARAMETER_RANGE × VALIDITY × SIGNATORY`，每行独立计算。契约里**不存在**任何报告级或机构级 `accredited` 布尔字段——契约测试直接反射断言这一点，让 RPT-CLAIM-001 在类型层面无法被违反。混合认可报告合法：认可行携带标识，非认可行 `ClaimsAccreditation=false` 且不得携带认可声明。

认可范围正文留在外部权威系统（OD-030 边界），`IAccreditationScopePort` 只回读被引用的六维快照。默认实现 `UnresolvedAccreditationScopePort` 什么都解析不出来——认可权威来源属未决 OD-012，因此**开箱即失败关闭**，部署方必须显式注册真实来源。

## EVALUATED 分区为何一律阻断

AC-TRACE-001 要求 `EVALUATED` 报告行追溯 `ConformityDecision`，而该对象依赖**未决的 OD-034**（检测结论层级与全面合规引用边界）。按 PRD"未决事项不得以默认假设进入生产配置"，门禁对 `LABORATORY_CONCLUSION` 分区的行返回 `CONFORMITY_DECISION_UNAVAILABLE` 阻断，而不是猜一个结论。

## 明确不在本卡范围

电子签名与内容哈希绑定、不可变版本链与五种受控动作、验证页、报告文件渲染（均属 DEV-023）；ConformityDecision 与全面合规引用（OD-034 未决）；分包对象与分包方回传（OD-013 未决）。

## 对抗式评审修正（四项真实缺陷）

| 缺陷 | 修正 |
|---|---|
| 门禁只扇出 6 个端口，**结果采用端口缺席**（三名验证者独立确认） | 补为第七个来源，按行固定的组版本回放采用端口；并把「仍 ALLOWED 但有效采用目标已变」判为 BLOCKED——只检查"还读得到"不等于 RULE-005 要求的"当前有效" |
| QC 可报告性**只问一个运行** | 报告行改为引用**一组** QC 运行（`report_line_qc_run` 子表，追加式），门禁逐个询问，每个不通过的运行各出一条阻断 |
| 签发门禁端口**回放过期 ALLOWED** | 评估后仍可追加行（状态仍 DRAFT），端口原样返回旧决策。以「认可判定条数 ≠ 报告行数」作为新鲜度判别——版本号无法表达，因为合法提交本身也会让报告比其评估前进一版 |
| 收样端口传入**认可 SiteId** 而非 LaboratoryId | 改传报告自身的 `ObjectScope.LaboratoryId`；测试夹具把认可 SITE 维度改成注册号形状（`CNAS-L1234-S1`），使参数错位再也无法藏身 |

共 15 项候选发现，逐项反驳验证后确认 4 项、驳回 11 项。

# 报告签名与不可变版本链（DEV-023 / ATC-RPT-002）

报告链后半。OD-011（CNAS/CMA + 电子签名法）与 OD-022（版本链取代）已决，本卡无需新决策。

## 内容哈希是整个设计的支点

`ReportVersionRules.Canonicalize` 把报告规范化为一段文本：报告号、版本号、规则集、对象范围，以及**按行号排序**的每行「采用目标 + 组版本 + 范围行 + 范围分区 + 认可判定 + 贡献链引用 + 认可范围引用」。SHA-256 之后就是签名绑定的对象（RPT-SIGN-001）。

这个设计让 **SEC-SIGN-002 自动成立**：被签内容变一个字，哈希就变，签字人当初同意的那个哈希对不上，签发被拒。不需要额外写一条"内容变了要作废签名"的规则——它是哈希的数学性质。

签发三要素（SEC-SIGN-001）缺一不可：重新认证证据引用、显式签署意图文本、期望内容哈希。

## 五种受控动作

| 动作 | 语义 | 约束 |
|---|---|---|
| `CORRECTION` / `SUPPLEMENT` | 产生序号加一的新版本 | **必须**携带影响评估引用；就地修改被拒（RPT-VERS-001） |
| `WITHDRAWAL` | 标记该版本停止被依赖 | 不产生新版本、不删除记录；同一版本只能撤回一次 |
| `VOID` | 终止整条报告链 | 唯一索引保证一条链只能作废一次；此后拒绝一切动作 |
| `SUPERSESSION` | 以新报告号记录取代关系 | 必须给出新报告号；唯一索引保证一条链只能被取代一次 |

链状态从追加式动作日志派生，不存可变状态列。

## 旧引用永远返回旧内容

`GET /versions/{n}` 始终返回第 n 版**自身**的快照与哈希，无论后来发生什么（RPT-VERS-004）。验证页则给出当前有效版本、每个历史版本的状态与取代关系（RPT-VERS-003）。撤回与作废都不删除任何已发生事实（RULE-011），全部由数据库触发器强制（55000）。

## 一处健壮性修正

写集成测试时发现：门禁评估原本按 `evaluated_at` 排序，而固定时钟下两次评估时间戳相同，"最新评估"就成了随机 GUID 决定的抛硬币。已改为按单调递增的 `report_version` 排序——受控判定的"最新"绝不能靠墙上时钟。受控动作排序同样改为按版本号确定。

## 对抗式复核补上的两个洞

一、`SUPERSESSION` 原本是五种动作里唯一没有重复防护的：领域层只特判了「已撤回」和「已被取代」，数据库唯一索引也只覆盖另外四种。两次相同的 POST（例如响应超时后客户端重试）会各写一行——而 `controlled_action` 带追加式触发器，UPDATE 与 DELETE 都被拒，重复事实一旦落库就**永久无法更正**。BUS-RPT-005 不变量 7 明确要求「同一版本的同一受控动作不得重复」，取代不在豁免之列。现在领域层按 `chain.SupersedingReportNumber` 拦截，数据库按链级唯一索引兜底。

二、`WITHDRAWAL` / `VOID` 携带空白取代号时，领域层用 `IsNullOrWhiteSpace` 判「缺省」，而持久化层与 CHECK 约束按 NULL 判——空串因此绕过校验直撞 23514，被 `FailAsync` 报成 `RPT.PERSISTENCE_UNAVAILABLE`/503。调用方的输入错误必须是 400。两层现在对"缺省"取同一个定义：NULL。

## 明确不在本卡范围

外部签章系统接入（OD-011 明确 Release 1 不接）、报告文件/PDF 渲染、客户交付渠道、面向公众的验证页前端。
